# Skills Evidence Matrix

| Capability | HomeyB | Parky | TCS foundation |
| --- | --- | --- | --- |
| Problem definition | Local context and privacy-conscious interaction | Vehicle recall across GPS and contextual memory | Translating operational signals into actionable findings |
| Requirements | PRD, rules, stories, acceptance criteria | BRD/PRD, stories, exceptions, non-functional requirements | Recurring reporting and controlled operational procedures |
| Process analysis | AS-IS / TO-BE flows and location-dependent exceptions | Save/find journeys and failure paths | Incident, maintenance, and restoration workflows |
| Prioritisation | Core discovery, safety, freshness, and evidence-gated roadmap | Explicit save, accuracy, clues, and offline guidance | SLA, continuity, and production-risk priorities |
| Data / metrics | Funnel, retention, reliability, safety, and cost measures | Save/find completion, confidence, and failure measures | SQL, Excel, Power BI, utilisation and performance reporting |
| Validation | RTM, UAT, two-device tests, permissions, offline recovery | Acceptance criteria, device validation, weak-signal plan | Evidence-based incident and root-cause support |
| Business/technical trade-offs | Real-time feel versus infrastructure cost; monetisation versus interruption | Privacy versus sync; compass versus maps; control versus automation | Reliability, change, continuity, and operational control |
| Communication | Product artefacts, risks, decisions, and release gaps | Structured evidence register and roadmap | Documentation and coordination across technical stakeholders |
